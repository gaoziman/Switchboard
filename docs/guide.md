# Switchboard 使用说明

[English](guide.en.md)

Switchboard 把 Claude Code、Codex、OpenCode、omp 留在这台 Mac 和 SSH 主机上的会话收进一个侧栏：先读对话，再决定在哪接着跑。

<a id="start"></a>
## 上手

1. 打开 Switchboard，侧栏只显示**你添加的文件夹**和里面四个 CLI 的会话。侧栏是空的时候点「添加一个文件夹」挑一个，也可以把文件夹从访达拖进侧栏。第一次读取会话可能要几秒，之后走缓存。
   从旧版本升级上来时会弹一次挑选：列出发现过会话的文件夹，默认勾上置顶的、上次开着标签的、最近 14 天用过的。
2. **单击**一个会话：在右边读对话，不启动 CLI。
3. **双击**（或预览里的「接着跑」）：在原来的项目目录里打开一个终端标签，CLI 接着这个会话跑。
4. 侧栏右上的 **+**（⌘N）开一个新会话：选 CLI、选项目文件夹。

需要的 CLI 自己装好、在登录 shell 的 `PATH` 里能找到即可。Switchboard 用你的登录 shell 环境启动它们。

<a id="library"></a>
## 会话库

- **项目 / 已打开**：顶部切换「按项目看全部会话」和「只看已经开着的标签」。
- **添加文件夹**：右键「这台 Mac」› 添加文件夹…，或者把文件夹从访达拖进侧栏。SSH 主机：右键主机名 › 添加文件夹…，从主机上发现过会话的文件夹里勾，主机上还没有会话的文件夹可以直接填路径（`~/项目` 也行）。
- **从侧栏移除**：右键项目 › 从侧栏移除。只是不显示，会话文件、置顶、重命名都留着，以后加回来还在；里面开着的标签不受影响。
- **库外有会话在跑**：没添加的文件夹里有 Claude Code 在跑时，侧栏底部会提示，点「添加到侧栏」或「忽略」（忽略过的文件夹不再提示）。
- **右键项目**（或悬停项目行点「…」，点「+」直接新建）：新建会话、新建终端、在 Finder 中打开项目、打开项目于（装了的编辑器和终端）、复制项目路径、重命名项目…（只改侧栏里显示的名字）、置顶、归档、从侧栏移除、删除所有可删除的会话（在跑的、开着标签的不算）、归档项目并删除所有会话。
- **右键会话**：接着跑、分叉为新会话（Claude Code、Codex、OpenCode）、结束会话（结束 CLI，会话文件保留）、移到…（只有 Claude Code，见下）、重命名、置顶、归档、拷贝或导出对话（Markdown、纯文本、原始会话文件）、复制会话 ID、在访达中显示、删除。
- **多选**：⌘-点按、⇧-点按选多个，底部出现批量操作；Esc 取消。
- **搜索**（侧栏顶上的放大镜）：搜标题和全部消息内容。第一次搜索要建索引，之后很快。
- **过滤**：只看最近 7 天、某个 CLI、在运行的、在等你的。
- **子代理**：设置 › 通用 › 会话库里打开后，Claude Code 的子代理会话会列在发起它的会话下面。
- **删除**：Claude Code、omp 的会话文件移到废纸篓；Codex、OpenCode 调用它们自己的删除命令，是永久删除；SSH 主机上没有废纸篓，也是永久删除。确认框里会写明。

**移到另一个文件夹**（只有 Claude Code）：右键会话 › 移到…，选同一台机器上的另一个项目（本机还可以选「其他文件夹…」）。Switchboard 在原来的目录里恢复会话，第一条消息发 Claude Code 自己的 `/cd <文件夹>`，由 Claude Code 搬对话记录；在没干过活的文件夹里它会先在终端里问你。会话的 CLI 正在跑时不能搬，先结束它。

置顶、重命名、归档存在 `~/Library/Application Support/Switchboard/`，不改 CLI 自己的任何文件。

<a id="terminal"></a>
## 终端和标签

- 标签按项目分组，像 Chrome 的标签组。⌘1–8 切到第几个，⌘9 最后一个，⇧⌘[ / ⇧⌘] 或 ⌃Tab 轮换。
- **分屏**：⌥⌘N，再选一个标签放到右边。
- **拖动标签**：在同一个项目组里拖动调顺序；拖到另一个窗口的标签栏就搬过去；拖到所有窗口外面松手，开一个新窗口放它。右键标签也有「移到新窗口」「移到窗口」。搬过去的终端不会重启。
- **多个窗口**：⇧⌘N 开新窗口。会话库所有窗口共用一份，标签各窗口自己的；关掉窗口时它的标签里的 CLI 留在 tmux 里接着跑。
- **保活**：CLI 跑在 Switchboard 自带的 tmux 里。关标签时可以选「让它继续跑」，或者在设置 › 主机里给每台机器设好默认做法；退出 Switchboard 也不会结束这些 CLI。下次点会话（或重新打开 app 恢复标签）会直接接上。
- **普通终端**：新会话里选「终端」开一个登录 shell，它不走 tmux，关掉就结束。
- 把文件拖进终端会粘贴路径；⌘-点按终端里的文件路径或链接会打开它（用什么打开见设置 › 通用）。
- ⌘F 查找，⌘+ / ⌘− / ⌘0 调终端字号。
- **终端引擎**：设置 › 终端里可以选 SwiftTerm（默认）或 Ghostty（GPU 渲染，大量输出时更流畅）。只对之后新开的标签生效。Ghostty 标签暂时不支持 ⌘F 查找；字体选「系统等宽」时它用自带的字体。

<a id="status"></a>
## 状态灯和通知

每个会话前面的灯（颜色以默认主题为准）：

| 灯 | 意思 |
|---|---|
| 转圈 | 正在工作 |
| 强调色的点（默认珊瑚橙） | 在等你回答（权限确认、提问） |
| 蓝点 | 跑完一轮，你还没看 |
| 绿点 | 在运行、空闲 |
| 空心圈 | 已经结束 |

- 跑完一轮、停下来等你时发系统通知（设置 › 通用 › 通知里可以分别关）。点通知直接打开那个会话。
- 侧栏顶上的铃铛列出所有在等你的会话。
- Claude Code 的状态在任何地方启动都能读到；Codex、OpenCode、omp 的细分状态只对**从 Switchboard 里启动**的会话有效（Switchboard 启动时给它们加了上报状态的参数或插件）。

<a id="ssh"></a>
## SSH 主机

1. 侧栏底部「添加 SSH 主机…」，填 `~/.ssh/config` 里的别名，或 `user@hostname`。端口、密钥、跳板机这些写在 `~/.ssh/config` 里。
2. Switchboard 用后台方式（不弹密码）试连一次，查主机上有没有 rsync、tmux 和各个 CLI。
3. 主机上四个 CLI 的会话都会镜像到这台 Mac（需要主机上有 `rsync`），列在主机名下面，同样可以读、接着跑、删除。OpenCode 的库里还有它的账号和凭据，所以不整个拷：Switchboard 在主机上用 `python3` 做一份只含会话的快照再拷过来。
4. 主机上装了 tmux 时，远程会话同样保活；没装的话连接断开 CLI 就会结束。

**要密码或验证码的主机**：在主机标题上点「连接…」，Switchboard 会把 ssh 的提问（密码、验证码、主机指纹）搬进对话框。登录一次之后，后台刷新、删除、标签都共用这条连接，不会再问。Switchboard 不保存你输入的任何东西。

**断线**：连接断开的标签会自动重连（2 秒、5 秒、10 秒……逐渐拉长，约 15 分钟后停止）；Mac 唤醒或 app 回到前台时立即再试。

<a id="ssh-startup"></a>
### 主机的 shell 启动脚本

Switchboard 用 `$SHELL -lc` 在主机上启动 CLI，读登录脚本（`~/.profile`、`~/.bash_profile`、`~/.zprofile`），不读交互脚本。常见问题：

- **CLI 找不到**：nvm、fnm 之类写在 `~/.bashrc` 的「非交互就退出」判断后面，登录 shell 里没有 node。把那几行挪到判断前面，或者挪进 `~/.profile`。
- **登录脚本里 `exec zsh`、自动 `tmux attach`**：会让后台命令卡住。只在你自己交互登录时执行：

```sh
if [[ $- == *i* ]] && [ -z "$SWITCHBOARD" ]; then exec zsh -l; fi
```

「检查这台主机…」会把这些问题找出来。

<a id="forwarding"></a>
## 端口转发

右键主机标题 › 转发端口…：列出主机上在 localhost 监听的端口，选一个（或手填），本机端口默认同号。转发只在这台 Mac 的 localhost 上监听，别的电脑连不进来。建好后右键菜单里可以在浏览器打开、拷贝地址、停止转发。断开或移除主机时转发会一起停掉。

<a id="check"></a>
## 检查主机

右键主机标题 › 检查这台主机…：只读地依次检查登录、shell 启动脚本、rsync、tmux（包括升级后旧 tmux 服务器连不上的情况）、各个 CLI 能不能跑，每一步显示耗时。每条发现都附主机的原话和一条可以在终端里复现的命令。

- 「复制报告」：发给别人帮你看。
- 「用 agent 修复…」：在这台 Mac 上开一个 Claude Code 会话，把报告交给它，它会用 ssh 去查、去修，改动主机之前先问你。

<a id="sign-in"></a>
## 定期重新登录

有些主机登录后还要隔一阵重新认证（比如 Kerberos 的 `kinit`）。右键主机标题 › 重新登录命令…：

- **命令**：在主机的登录 shell 里、带终端运行，比如 `kinit`。命令问的东西会搬进对话框。
- **检查命令**（可选）：退出码 0 表示还有效，比如 `klist -s`。每 5 分钟跑一次。
- 没有检查命令时按间隔（小时）算。

到期时主机标题出现「登录…」，并发一条系统通知。

<a id="appearance"></a>
## 外观和语言

- 设置 › 外观：6 套主题，各有浅色和深色；明暗可以跟随系统。
- **自定义颜色**：在外观里改当前主题的背景、侧栏、面板、文字、强调色，浅色和深色分开改，马上生效；按钮上的字会自动选黑或白。换主题再换回来，改动还在；「全部还原」回到主题自己的颜色。
- **界面大小**：90%–150%，侧栏、标签、对话框里的文字跟着放大缩小（终端字号单独在「终端」里设）。
- 设置 › 终端：终端配色（跟随 app 主题、内置配色，或导入 iTerm2 的 `.itermcolors`）、字体、字号、颜色强度。
- 设置 › 通用 › 界面语言：跟随系统 / 简体中文 / English，重新启动后生效。会话标签会重新打开，CLI 在 tmux 里接着跑；普通终端会关掉。

<a id="privacy"></a>
## 隐私

- Switchboard 只读取各 CLI 保存在本机（和你添加的主机）上的会话文件，不上传任何内容。
- 不保存你在登录对话框里输入的密码、验证码。
- 联网只有两处：每天检查一次更新（GitHub Releases，可以在设置 › 帮助里关掉）；你主动点「发送反馈」「报告问题」时在浏览器里打开 GitHub。
- 崩溃报告：上次意外退出时，下次启动会问你要不要报告。报告内容只有版本、异常和调用栈，不含你的文件路径；不点就什么都不发。

<a id="troubleshooting"></a>
## 故障排查

**侧栏里没有某个文件夹的会话**：侧栏只显示添加过的文件夹，先把它加进来（右键「这台 Mac」› 添加文件夹…）。

**侧栏里没有某个 CLI 的会话**：确认用这台 Mac 上的这个 CLI 跑过会话，并且它的数据目录在默认位置（`~/.claude`、`~/.codex` 等）。⌘R 重新读取。

**双击会话，终端里提示找不到命令**：CLI 不在登录 shell 的 `PATH` 里。在「终端」app 里运行 `$SHELL -lc 'command -v claude'` 看看能不能找到。

**主机标题显示「要密码或验证码」**：点「连接…」登录一次。之后的刷新共用这条连接。

**主机上的会话不出现**：主机上要有 `rsync`（Debian / Ubuntu：`sudo apt install rsync`）。右键主机 › 检查这台主机… 会告诉你缺什么。

**主机上 CLI 启动不了，但手动 ssh 上去能用**：多半是 shell 启动脚本的问题，见[主机的 shell 启动脚本](#user-content-ssh-startup)。

**状态灯不变**：Codex、OpenCode、omp 的细分状态只对从 Switchboard 启动的会话有效。

**还是不行**：帮助 › 报告问题…，会打开 GitHub 的问题表单，版本号已经填好。附上「检查这台主机」的报告会很有帮助。
